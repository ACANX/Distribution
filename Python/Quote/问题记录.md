# 问题记录

## 001 — Open 计算精度丢失

### 问题描述

对 Latest.mvsv 做 8→11 列扩展时，第一条记录的开盘价（Open）通过 `Open = Close - ChangePrice` 计算。直接使用 Python `float` 运算后 `str()` 转换导致精度丢失。

**示例（518880）**：

```
Close = "9.001", ChangePrice = "-0.251"
期望: Open = "9.252"
实际:  Open = "9.251999999999999"
```

### 原因

Python `float` 是 IEEE 754 双精度浮点数（64-bit），`9.001 - (-0.251)` 在二进制中无法精确表示，浮点运算结果为 `9.251999999999999...`。直接用 `str()` 转换暴露了内部表示精度。

### 排查过程

1. 首次修复尝试：使用 `round(value, 6)` 统一保留 6 位小数
   - 问题：Open 的精度与输入不一致。例如 `Close=135, CP=0` → `Open="135.000000"` 不应有多余的 0

2. 最终方案：**从输入字符串提取精度位数，按 max(prec_close, prec_cp) 格式化输出**
   - 读取 Close 和 ChangePrice 的字符串原始值
   - 统计小数点后的位数
   - 取两者最大位数作为输出精度
   - 用 `format(value, f".{prec}f")` 格式化

### 解决方案

`mvsv.py` 中 `_expand_to_11cols` 函数新增 `_calc_open` 辅助函数：

```python
def _calc_open(close_str, cp_str):
    prec = max(
        len(close_str.split(".")[1]) if "." in close_str else 0,
        len(cp_str.split(".")[1]) if "." in cp_str else 0,
    )
    return format(float(close_str) - float(cp_str), f".{prec}f")
```

### 验证结果

| 证券 | Close | ChangePrice | precision | Open |
|---|---|---|---|---|
| 518880 | 9.001 (3位) | -0.251 (3位) | 3 | **9.252** ✅ |
| GCMain | 4352.2 (1位) | -1.7 (1位) | 1 | **4353.9** ✅ |
| NVDA | 210.155 (3位) | 5.055 (3位) | 3 | **205.100** ✅ |
| SPCX | 135 (0位) | 0 (0位) | 0 | **135** ✅ |
| USDCNY | 6.7655 (4位) | 0 (0位) | 4 | **6.7655** ✅ |

## 如何规避此类问题

浮点数精度问题是工程中的常见陷阱，以下规范可有效规避：

### 1. 凡是金额/价格计算，绝不直接 str(float)

```python
# ❌ 错误
open_val = str(float(close) + float(cp))

# ✅ 正确
prec = max(close_decimal_places, cp_decimal_places)
open_val = format(float(close) - float(cp), f".{prec}f")
```

### 2. 字符串到字符串的数值转换，先确定精度再输出

mvsv 中所有数值字段以字符串形式存储，任何数值计算（加减乘除、汇总）都必须：
1. 读取输入字符串
2. 确定输入精度（小数点后位数）
3. 计算（可用 float 或 Decimal）
4. 按确定的精度格式化输出

### 3. 在代码审查中检查精度路径

涉及以下操作时必须检查精度处理逻辑：
- 从现有字段计算新字段（如 Open 从 Close + ChangePrice 推导）
- 多行聚合（如求和、平均）
- 字段类型转换（如 str → float → str）

### 4. 优先使用 format() 而非 round()

| 方式 | 问题 |
|---|---|
| `str(9.001 - (-0.251))` | 暴露 float 内部精度 `9.251999999999999` |
| `round(9.001 - (-0.251), 6)` | Open="9.252000"，多余尾部 0 |
| `format(9.001 - (-0.251), ".3f")` | **推荐**，精度匹配输入 |

### 5. 测试边界值

添加包含以下特征的用例：
- 整数结果（Close=135, CP=0 → Open="135"）
- 不同精度输入（Close=6.7655, CP=0 → Open="6.7655"）
- 纯整数输入（Close=100, CP=10 → Open="110"）
- 高精度输入（Close=0.0001, CP=0.00005 → Open="0.00005"）

### 6. 不在 mvsv 存储层使用 Decimal

不引入 `decimal.Decimal` 依赖，原因：
- mvsv 是文本格式，float 读取/写入一致性好
- Decimal 序列化后同等精度下与 format(float) 结果相同
- 避免引入第三方依赖
